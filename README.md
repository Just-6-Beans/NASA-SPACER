# SPACER

An educational browser game about orbital station operations and a delayed Mars rover survey, inspired by the NASA Space Apps Challenge. You pick a spacecraft, crew the station, prepare a rover, repair a relay, send a Mars survey plan across the light-speed delay, wait for evidence, and decide whether and where to land.

**Two rover numbers are real NASA data; the rest is simulated.** The signal delay is the real Earth to Mars light time for the operations date you pick (JPL Horizons), and the night cold is a real Curiosity REMS measurement at Gale Crater. Terrain, ice readings, drive and scan times, costs and the station orbit are game rules, and the game labels them. No NASA branding is used.

Stack: Phaser 3.90 (Arcade Physics), TypeScript, Vite, HTML/CSS interface, Colyseus co-op. All art is original: vector artwork generated by `scripts/gen-art.mjs` and bundled in `public/assets/`, plus the title screen's Mars globe, which is drawn at run time by a WebGL2 shader (`src/ui/titleScene.ts`). The globe is a procedural artist's impression, not a NASA image.

This is our team's entry for the NASA Space Apps Challenge 2026 challenge [Space Mission Design Game](https://www.spaceappschallenge.org/2026/challenges/space-mission-design-game/). It is a fresh build of Spacer. The original prototype is in [Space-Mission-Design-Game](https://github.com/Just-6-Beans/Space-Mission-Design-Game).

## Set up a device

```bash
git clone https://github.com/Just-6-Beans/NASA-SPACER-Claude.git
cd NASA-SPACER-Claude
npm ci
npm run check    # type-check and tests
npm run dev      # then open http://127.0.0.1:5173/
```

In Windows PowerShell, use `npm.cmd` in place of `npm`. Then take a lane and start its branch:

```bash
git checkout -b lane/data        # or lane/rules, lane/experience
```

Write your name at the top of `notes/<lane>.md` and follow the working rules in [CHALLENGE.md](CHALLENGE.md#5-three-devices-three-lanes).

## Working as a team

Everyone works on one repository and lands on `main`, so the repo itself keeps people from stepping on each other:

- **Lanes own files.** [lanes.json](lanes.json) lists which files belong to the data, rules and experience lanes, which are frozen (co-op), and which only a human changes. It mirrors CHALLENGE.md section 5.
- **`npm ci` turns on a pre-push hook** ([.githooks/pre-push](.githooks/pre-push)). When you push to `main` it:
  - refuses to overwrite commits a teammate already pushed, so pull first (`git pull --rebase origin main`);
  - runs `npm run lane-check`;
  - runs `npm run check`.
- **`npm run lane-check`** compares your `lane/<name>` branch with `main`:
  - Another lane's file is allowed only if a commit message names the file.
  - Another lane's notes file is never allowed.
  - Frozen files, human-only files and new dependencies need a `Human-approved: <who>, <what>` line in the commit message.
- **GitHub Actions** ([.github/workflows/check.yml](.github/workflows/check.yml)) runs the same checks on every push to `main` and every pull request, and also checks that `public/assets` matches `src/art/geo.json`. A red run means `main` needs fixing before anything else.
- **Claim work before you start it** under "Now" in your lane's notes, and read the other two notes files after every pull.
- **Same environment everywhere:** the repo has a dev container ([.devcontainer/](.devcontainer/devcontainer.json)). Open it in GitHub Codespaces or with VS Code's Dev Containers extension to get Node 22 and an installed project. For co-op inside Codespaces, build with `VITE_COOP_URL` set to the forwarded address of port 2567.

## Run it

Needs Node.js 20.19+ or 22.12+.

```bash
npm ci
npm run dev
```

Open **http://127.0.0.1:5173/**. Keep the terminal open while you play.

For co-op, run the service in a second terminal and keep it running too:

```bash
npm run server
```

It listens on `ws://127.0.0.1:2567`. To use another service, build or run with `VITE_COOP_URL=ws://host:port`. Solo play does not need the server.

Other commands:

| Command | What it does |
| --- | --- |
| `npm run build` | Type-check and build to `dist/` |
| `npm run preview` | Serve the built game at http://127.0.0.1:4173/ |
| `npm run check` | Type-check, then `npm test` |
| `npm run lane-check` | Check that this lane branch only changes what its lane owns (see [Working as a team](#working-as-a-team)) |
| `npm test` | Mission rules, acceptance scenarios, and a live two-client co-op test |
| `npm run art` | Regenerate the SVG artwork |
| `npm run data` | Download the NASA snapshots again into `data/nasa/`, then rebuild the operations dates (needs a network connection; the game itself never does) |
| `npm run data:ops` | Rebuild `data/nasa/ops-dates.json` from the committed snapshots (offline) |

On Windows you can double-click `play.bat`. It installs dependencies if needed, starts the co-op service and the game, and opens the browser.

## Five-minute walkthrough

1. **Solo mission** → choose a spacecraft → enter a call sign and pick a suit → **Launch** (or **Skip animation**). For two players, choose **Co-op mission** instead (see below).
2. You dock at the station. Walk up to **Payload**, just ahead of you. Pick an instrument and **Activate payload**. The relay faults.
3. Go to **Rover Comms** (rear right) and rotate the receiver segments to match the reference. **Confirm match**.
4. At **Power Grid** (rear left), raise Communications to at least 4. At 5 the link is direct and skips the relay hand-off on each signal leg. Research at 3 or more cuts uncertainty instead.
5. Optional: at **Calibration** (front right), tune gain and offset until both standards turn green. Optional routine tasks: battery balancing, cargo, water, medical.
6. Back at **Rover Comms**, open the planner. It has three steps: pick an **operations date**, a **route** and a **scan**. The date sets two real numbers, the signal delay and the night cold. Read the battery and clock forecast, and **Transmit sequence**.
7. Advance the clock with **Next event**, **+5 min** or **Run clock**. Evidence counts only once it reaches Earth.
8. **Review landing sites**: select a site and **Confirm site**, or defer. Read the report and commission the habitat if your crew passed the medical check. Then **Replay with this crew** or **Return to title**.

## The station

Three pressurised nodes in a row, joined by open hatches. You arrive through the airlock in node B, and the floor guide leads you to the mission brief. You can walk behind the freestanding consoles.

| Node | Rear wall | Front |
| --- | --- | --- |
| **A · Utility** | Power Grid, beside the power core. Your ship is docked outside the window. | Hab Systems: water, hydroponics, medical |
| **B · Command** | The cupola, with the Mission Ops holo-table in front of it | The rover bay (Payload) and the airlock |
| **C · Science & Comms** | Rover Comms. The relay dish is outside the window. | The Calibration bench |

The deck shows mission state, so you can read your choices off the room:

- **Power buses** in the floor run from the Power Grid to Hab Systems (life support), Rover Comms (communications) and the Calibration bench (research). Each glows with the units routed to it, and turns amber while it is below what transmission needs.
- **Consoles** show live values: the allocation on the Power Grid, the one-way signal delay on Rover Comms (split into the JPL Horizons light time and the relay hand-off), the rover's starting charge in the bay, and lamps for calibration, water and medical.
- **The rover** carries the instrument you chose at Payload.
- **Relay fault**: the beacon flashes, the dish hunts for the carrier, and the link display reads NO LINK until you repair it.
- **Mission Ops** has three tabs: the mission brief; a live mission status (budget, mass, power, battery and time against their limits, what is deciding the rover pass, and the three operations dates compared side by side, where you can also pick one); and the data sources, which name the two NASA datasets with their place, date and limits and say which numbers are our model.

## Two-tab co-op

1. Run `npm run server` and `npm run dev`.
2. Open http://127.0.0.1:5173/ in two tabs or windows. Use different call signs and suits.
3. In each tab, choose **Co-op mission** on the title screen. The cards flip to the crew link, which joins the room and shows both seats filling. Press **Continue to spacecraft** and launch as usual; the link stays up through docking. (You can still join later from the station: **Co-op** → **Join co-op room**.)
4. Each tab shows the other astronaut, its name and its suit. Walk in one tab and watch the other.
5. Change power in one tab, for example Communications 3 → 4. The other tab's meters update immediately. Clocks, tasks, rover and landing stay per player.
6. A crewmate disappears while they are in the rover view or on the title screen, and reappears when they return. **Leave room** or closing the tab removes them.

If the service is offline, the crew link says so and offers **Retry** or **Fly solo instead**; the in-station Co-op panel offers **Retry**. Solo play continues. Choosing **Solo mission** on the title leaves any room you had joined.

## The rover pass: real data and our model

The planner offers three operations dates. Each one carries two real measurements, read from snapshots in `data/nasa/` (the game never calls an API):

| Operations date | One-way light time | Night low at Gale Crater | Heater draw (our model) |
| --- | ---: | ---: | ---: |
| 30 Mar 2029 | 5.4 min | −79 °C (sol 4580, 25 Jun 2025) | 14 pts |
| 15 Jul 2029 | 10.4 min | −74 °C (sol 4685, 10 Oct 2025) | 9 pts |
| 15 Nov 2029 | 15.8 min | −66 °C (sol 4804, 10 Feb 2026) | 1 pt |

- **Light time** is from JPL Horizons (Mars seen from Earth, daily, 2026 to 2030). 30 Mar 2029 is the closest approach in that record.
- **Night low** is from the Curiosity REMS weather feed, an outreach product for one place, Gale Crater. REMS has no measurement for a future date, so each date borrows the sol two Mars years earlier, which is the same season. That stand-in is our model.
- The trade-off is in the data: the closer Mars is, the colder the night at Gale Crater.

What the game does with those two numbers is our model:

- **Signal leg** = light time + relay hand-off. Communications at 5 or more is a direct link and skips the hand-off. Nothing shortens the light time.
- **Heaters** use 1 battery point for each °C the night low is below −65 °C, before the pass starts.
- **Rover reserve:** the battery floor is 20%. A command that would cross it runs only partway, then the rover enters safe mode and stays where it is. A stranded rover holds any landing at Ares Shelf.
- **Dust front (simulated):** Ares Shelf closes if the final telemetry arrives at T+56 or later.

## Simulated rules in brief

| Ship | Payload | Budget | Rover battery | Relay hand-off |
| --- | ---: | ---: | ---: | ---: |
| Odyssey | 18 kg | 100 cr | 100% | 3 min |
| Atlas | 25 kg | 113 cr | 92% | 3 min |
| Vector | 12 kg | 88 cr | 100% | 2 min |

- **Instruments:** IR-S1 costs 42 cr and weighs 7 kg, with a quick-scan draw of 6 points and ±19 uncertainty. GPR-2 costs 68 cr and weighs 13 kg, with a draw of 18 points and ±11 uncertainty.
- **Routes:** Ridge bypass takes 16 min and 25 points per driving leg. Basin shortcut takes 10 min and 29 points per leg. Battery balancing saves 3 points per leg.
- **Scans:** a deep scan takes 8 min instead of 4, uses 8 extra points, and cuts uncertainty by 7.
- **Ice reading:** the estimate is 31%. Calibration cuts uncertainty by 5; skipping it adds 9. Research filtering cuts 5. Minimum uncertainty is ±3. Evidence is strong when the low end is 22% or more.
- **Meridian Plain:** needs 26 cr of water plus a 12 cr power kit. The water task saves 8 cr; the cargo task adds 5 cr to your budget.

No date and no design wins everywhere. The frugal spectrometer needs time for its deep scan, so it suits the close, cold date and never clears Ares Shelf from 15.8 light-minutes. The power-hungry radar reads well from a quick scan, so it can afford the fast route when the nights are warm. `npm test` checks this over every ship, instrument, date and plan.

## Acceptance scenarios (verified by `npm test` and in the browser)

1. Odyssey, calibrated IR, power 3/5/2, 30 Mar 2029, ridge, deep scan. Signal legs are 5.4 min and the heaters take 14 points. The scan arrives at T+34.8 as 31 ±7%, the rover ends at 22%, and final telemetry arrives at T+50.8, so Ares Shelf clears. With battery balancing the rover ends at 28%.
2. The same plan with power 3/4/3. Each signal leg now includes the 3 min hand-off (8.4 min). The evidence is strong, but final telemetry at T+56.8 means Ares Shelf has closed.
3. Odyssey, uncalibrated GPR, power 3/4/2, 30 Mar 2029, basin, quick sweep. The scan completes, the return stops at 20% in safe mode 10 points short, and the reading is weak. The stranded rover holds Ares Shelf. Meridian's 38 cr is more than the 32 cr left; the water task brings it to 30 cr, which you can afford.
4. Odyssey, calibrated GPR, power 3/5/2, basin, quick sweep. On 15 Nov 2029 (15.8 min, −66 °C) final telemetry arrives at T+55.6 with 23% left and Ares Shelf clears. The same plan on 30 Mar or 15 Jul 2029 strands the rover, because the colder night leaves too little battery. The plan from scenario 1 on 15 Nov 2029 arrives at T+71.6, long after the dust front.
5. Two tabs: both astronauts appear and move, power syncs, avatars hide and reappear, and solo works with the server offline.

## Project layout

- `data/nasa/`: NASA snapshots. `earth-mars-geometry.json` (JPL Horizons) and `curiosity-weather.json` (Curiosity REMS) are the trimmed downloads; `ops-dates.json` is the small extract the game reads. Each file records its source, provider and retrieval date.
- `src/data/`: typed access to that extract, plus the source lines the game shows.
- `src/core/`: pure TypeScript rules (data, power, tasks, rover simulation, mission, co-op protocol validation). This code is shared with the server and tests.
- `src/art/geo.json`: station and Mars geometry, read by both the art generator and the game.
- Station code: `src/game/deck.ts` (typed geometry), `src/game/stationFx.ts` (mission state drawn on the deck), `src/game/nav.ts` (the floor guide's route), `src/ui/ops.ts` (Mission Ops), `src/ui/stationHud.ts` (objective, deck map), `src/ui/forecast.ts` (the pass forecast those screens show).
- `src/game/`: Phaser scenes (station and Mars) and input.
- `src/ui/`: title (with its WebGL2 backdrop in `titleScene.ts`), fleet, crew, launch, task panels, rover operations, landing sites, and the report.
- `server/`: the Colyseus `spacer_power` room.
- `scripts/`: the art generator, the NASA download (`fetch-nasa-data.mjs`) and the operations-date builder (`build-ops-dates.mjs`). `test/` holds the tests.
