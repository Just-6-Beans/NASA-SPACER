# SPACER

An educational browser game about orbital station operations and a real Mars rover survey, inspired by the NASA Space Apps Challenge. You pick a spacecraft, crew the station, repair a relay, then choose one of NASA's rovers, Perseverance or Curiosity, and drive it across a real picture of its surroundings taken from orbit: tap points for it to drive to, watch its camera as it goes, photograph real photo spots on the way, test the ground wherever it stops, recharge when the battery runs low, and decide where the crew's base goes before the mission's ten Mars days run out.

**Real data, game rules on top.** The picture of the ground from orbit, the map heights, the places the rovers really parked (with their slopes and elevations), the photos, selfies and films, the Gale Crater weather, the radiation, the terrain roughness, the rover power figures and the signal delay (the real Earth to Mars light time from JPL Horizons) come from NASA (see [Rover expedition](#rover-expedition-perseverance-and-curiosity)). Station tasks, costs, the ten-day limit, the scores and the station orbit are game rules, and the game labels which is which. No NASA branding is used.

Stack: Phaser 3.90 (Arcade Physics), TypeScript, Vite, HTML/CSS interface, Colyseus co-op. All art is original: vector artwork generated by `scripts/gen-art.mjs` and bundled in `public/assets/`, plus the title screen's Mars globe, which is drawn at run time by a WebGL2 shader (`src/ui/titleScene.ts`). The globe is a procedural artist's impression, not a NASA image.

This is our team's entry for the NASA Space Apps Challenge 2026 challenge [Space Mission Design Game](https://www.spaceappschallenge.org/2026/challenges/space-mission-design-game/). It is a fresh build of Spacer. The original prototype is in [Space-Mission-Design-Game](https://github.com/Just-6-Beans/Space-Mission-Design-Game).

## Set up a device

```bash
git clone https://github.com/Just-6-Beans/NASA-SPACER-Claude.git
cd NASA-SPACER-Claude
npm ci
npm run check    # type-check and tests
npm run dev      # then open http://127.0.0.1:5173/
```

In Windows PowerShell, use `npm.cmd` in place of `npm`. Then take a lane and start its branch:

```bash
git checkout -b lane/data        # or lane/rules, lane/experience
```

Write your name at the top of `notes/<lane>.md` and follow the working rules in [CHALLENGE.md](CHALLENGE.md#5-three-devices-three-lanes).

## Working as a team

Everyone works on one repository and lands on `main`, so the repo itself keeps people from stepping on each other:

- **Lanes own files.** [lanes.json](lanes.json) lists which files belong to the data, rules and experience lanes, which are frozen (co-op), and which only a human changes. It mirrors CHALLENGE.md section 5.
- **`npm ci` turns on a pre-push hook** ([.githooks/pre-push](.githooks/pre-push)). When you push to `main` it:
  - refuses to overwrite commits a teammate already pushed, so pull first (`git pull --rebase origin main`);
  - runs `npm run lane-check`;
  - runs `npm run check`.
- **`npm run lane-check`** compares your `lane/<name>` branch with `main`:
  - Another lane's file is allowed only if a commit message names the file.
  - Another lane's notes file is never allowed.
  - Frozen files, human-only files and new dependencies need a `Human-approved: <who>, <what>` line in the commit message.
- **GitHub Actions** ([.github/workflows/check.yml](.github/workflows/check.yml)) runs the same checks on every push to `main` and every pull request, and also checks that `public/assets` matches `src/art/geo.json`. A red run means `main` needs fixing before anything else.
- **Claim work before you start it** under "Now" in your lane's notes, and read the other two notes files after every pull.
- **Same environment everywhere:** the repo has a dev container ([.devcontainer/](.devcontainer/devcontainer.json)). Open it in GitHub Codespaces or with VS Code's Dev Containers extension to get Node 22 and an installed project. For co-op inside Codespaces, build with `VITE_COOP_URL` set to the forwarded address of port 2567.

## Run it

Needs Node.js 20.19+ or 22.12+.

```bash
npm ci
npm run dev
```

Open **http://127.0.0.1:5173/**. Keep the terminal open while you play.

For co-op, run the service in a second terminal and keep it running too:

```bash
npm run server
```

It listens on `ws://127.0.0.1:2567`. To use another service, build or run with `VITE_COOP_URL=ws://host:port`. Solo play does not need the server.

Other commands:

| Command | What it does |
| --- | --- |
| `npm run build` | Type-check and build to `dist/` |
| `npm run preview` | Serve the built game at http://127.0.0.1:4173/ |
| `npm run check` | Type-check, then `npm test` |
| `npm run lane-check` | Check that this lane branch only changes what its lane owns (see [Working as a team](#working-as-a-team)) |
| `npm test` | Mission rules, acceptance scenarios, and a live two-client co-op test |
| `npm run art` | Regenerate the SVG artwork |
| `npm run data` | Download the NASA snapshots again into `data/nasa/`, then rebuild the operations dates (needs a network connection; the game itself never does) |
| `npm run data:ops` | Rebuild `data/nasa/ops-dates.json` from the committed snapshots (offline) |
| `npm run data:rovers` | Download the rover expedition's NASA snapshots, map tiles, pictures and films again (needs a network connection). Add `-- --only=satellite,pictures` to run just some steps |

On Windows you can double-click `play.bat`. It installs dependencies if needed, starts the co-op service and the game, and opens the browser.

## Controls

| Action | Keyboard | Touch |
| --- | --- | --- |
| Walk | WASD or arrow keys | On-screen d-pad |
| Jog | Hold Shift | ⇧ in the d-pad centre |
| Use nearest terminal | E (or click the terminal when close) | Orange E button |
| Close panel | Escape | Close button |
| Choose solo or co-op on the title | ← / →, then Enter | Tap a card |
| Change spacecraft | ← / →, arrow buttons, wheel, swipe | Swipe |

HUD buttons: **Tasks** (Routine, Mission and Emergency list), **Guide** (floor chevrons to the next objective, on by default), **Sound**, **Debug** (FPS, collision boxes, both clocks, +250 visual-only sprites up to 3,000), **Co-op**. The deck map in the corner shows the three nodes, you, your crewmate and the next objective.

On the rover screen, tap the map to place points for the rover to drive to. Use the zoom slider to look closer; when zoomed in, hold the right mouse button and drag to move the map (or drag with a finger). On the **Rover parts** tab, tap the glowing dots to learn what each part does.

## Five-minute walkthrough

1. **Solo mission** → choose a spacecraft → enter a call sign and pick a suit → **Launch** (or **Skip animation**). For two players, choose **Co-op mission** instead (see below).
2. You dock at the station. Walk up to **Payload**, just ahead of you. Pick an instrument and **Activate payload**. The relay faults.
3. Go to **Rover Comms** (rear right) and rotate the receiver segments to match the reference. **Confirm match**.
4. At **Power Grid** (rear left), raise Communications to at least 4. At 5 the link is direct and skips the relay hand-off, so the signal delay is shorter. Research at 3 or more makes rover drilling use 30 % less battery.
5. Optional: at **Calibration** (front right), tune gain and offset until both standards turn green so drilled samples are analysed. Optional routine tasks: battery balancing (driving draws 30 W less), cargo, water (+5 to the base score), medical.
6. Back at **Rover Comms**, open the rover screen. First you **choose your rover**: Perseverance in Jezero Crater or Curiosity in Gale Crater. Each card shows a real selfie, what that rover is good and not so good at, and a button to look at its parts. You keep the rover you choose for the whole mission.
7. **Tap the map** to place points. The rover drives them in order and the last point ⚑ is the spot it checks. Watch the battery and Mars-days forecast, then **▶ Start deployment**. The rover moves along your path while its camera plays a real drive film. When it drives into the ring around a camera mark, it saves that real NASA photo to your album by itself and adds to your score.
8. At the spot, **run tests** (Photograph, Weather, Radiation, Drill). The big answer at the top says whether it is a good place, a risky place or a bad place. Then **Build the base here**, good or bad, or **Explore another spot**. When the battery gets low, **Recharge**: it runs on a timer, and you can go back to the station while it charges. Read the report and commission the habitat if your crew passed the medical check. Then **Replay with this crew** or **Return to title**.

## The station

Three pressurised nodes in a row, joined by open hatches. You arrive through the airlock in node B, and the floor guide leads you to the mission brief. You can walk behind the freestanding consoles.

| Node | Rear wall | Front |
| --- | --- | --- |
| **A · Utility** | Power Grid, beside the power core. Your ship is docked outside the window. | Hab Systems: water, hydroponics, medical |
| **B · Command** | The cupola, with the Mission Ops holo-table in front of it | The rover bay (Payload) and the airlock |
| **C · Science & Comms** | Rover Comms. The relay dish is outside the window. | The Calibration bench |

The deck shows mission state, so you can read your choices off the room:

- **Power buses** in the floor run from the Power Grid to Hab Systems (life support), Rover Comms (communications) and the Calibration bench (research). Each glows with the units routed to it, and turns amber while it is below what sending the rover out needs.
- **Consoles** show live values: the allocation on the Power Grid, the one-way signal delay on Rover Comms (split into the JPL Horizons light time and the relay hand-off), the rover's battery in the bay (the charge it arrives with, then its gauge once you have chosen a rover), and lamps for calibration, water and medical.
- **The rover** carries the instrument you chose at Payload.
- **Relay fault**: the beacon flashes, the dish hunts for the carrier, and the link display reads NO LINK until you repair it.
- **Mission Ops** has three tabs: the mission brief; a live mission status (budget, mass, power, rover battery and Mars days, and one row for each choice saying what it is causing); and the data sources, which name each NASA dataset with its place, date and limits. The same rules drive the rover screen and the report.

## Two-tab co-op

1. Run `npm run server` and `npm run dev`.
2. Open http://127.0.0.1:5173/ in two tabs or windows. Use different call signs and suits.
3. In each tab, choose **Co-op mission** on the title screen. The cards flip to the crew link, which joins the room and shows both seats filling. Press **Continue to spacecraft** and launch as usual; the link stays up through docking. (You can still join later from the station: **Co-op** → **Join co-op room**.)
4. Each tab shows the other astronaut, its name and its suit. Walk in one tab and watch the other.
5. Change power in one tab, for example Communications 3 → 4. The other tab's meters update immediately. Clocks, tasks, rover and landing stay per player.
6. A crewmate disappears while they are in the rover view or on the title screen, and reappears when they return. **Leave room** or closing the tab removes them.

If the service is offline, the crew link says so and offers **Retry** or **Fly solo instead**; the in-station Co-op panel offers **Retry**. Solo play continues. Choosing **Solo mission** on the title leaves any room you had joined.

## Rover expedition (Perseverance and Curiosity)

**Choose your rover.** It is the first thing in the rover room, and the choice lasts the whole mission. Every pro and con on the cards comes from the numbers the game plays with.

| | Perseverance (Jezero Crater) | Curiosity (Gale Crater) |
| --- | --- | --- |
| Power source today | about 81 W | about 53 W |
| Reach on one charge, flat ground | about 1.6 km | about 1.2 km |
| Full recharge | about 1.1 Mars days | about 2.5 Mars days |
| Mass (climbing cost) | 1,025 kg | 899 kg |
| Where it starts | on a 7.3° slope, level enough for a base | on a 12.5° slope, too steep for a base |
| Crater roughness from orbit | 3.5 m | 4.1 m |
| Weather and radiation | borrowed from Curiosity's crater | measured in its own crater |
| Photo spots within 600 m of the start | 4 | 7 |
| Real stops on the map | 132 (tilt 0.9° to 20.7°) | 118 (tilt 3.2° to 24.0°) |

- **The map** is a 3 km square centred on where the real rover is. Its picture is real: the colour basemap of NASA's own "Where is the rover?" map, made from Mars Reconnaissance Orbiter HiRISE images (about 1.2 m per dot). A switch flips to a height map drawn from NASA's MOLA heights, with 20 m contour lines. The zoom slider goes to 6×; when zoomed in, drag the map, and it follows the rover while it drives. White dots are the places the rover really parked.
- **Battery:** one gauge, where 100 % is full and 0 % is NASA's safe-mode line (40 % of the real battery). Driving, tests and photos all use it. At 0 % the rover stops in safe mode until it is recharged.
- **Recharging:** when the gauge is at 50 % or less (or the rover cannot drive), a Recharge button appears. The rover parks while its nuclear power source refills the battery. The time is worked out from each rover's real power: what its MMRTG makes today minus a 30 W always-on load (our model). It runs on a real countdown, one Mars hour each second (about 30 seconds for a full Perseverance charge, a minute for Curiosity). The rover screen shows the battery now and the time left. You can go back to the station while it charges, stop early and keep what was gained, or skip the wait. The Mars days are used up either way.
- **Ten Mars days:** the mission lasts 10 sols. Driving counts at the real rover's top speed and recharging counts in full. When the days are used up, you build on a spot already visited or stay in orbit. The number 10 is a game rule, not a NASA figure.
- **Driving cost:** distance plus climb. Uphill costs more: the rover's mass times Mars gravity for every metre gained.
- **Photo spots:** camera marks on the map are places where the real rover took the photos saved in the game (16 per rover). There is nothing to press: when the rover drives within 120 m of one, or parks there, its real photos join your album and the spot adds +2 to the base score, up to +10. It costs no battery and each spot counts once. The plan shows how many spots a drive will pass. The album strip under the camera and the **My photos** tab open them full size.
- **A spot's slope:** within 75 m of a real rover stop, the tilt NASA measured there. Anywhere else, the average slope from the MOLA grid (about 460 m), and the game says so.
- **Tests:** Photograph (80 Wh, about 6 % of the gauge) fills Level ground. Weather (40 Wh, 3 %) fills Sunlight and Warmth, once for the whole region. Radiation (40 Wh, 3 %) fills Low radiation, once for the region. Drill (300 Wh with IR-S1, 380 Wh with GPR-2, about 21 % or 26 %) fills Rock sample. A test you cannot afford says so on its button.
- **Verdict:** more than 10° is a bad place. Level ground with a site score of 60 or more is a good place; otherwise it is risky. Unmeasured bars score 0. You can build on any spot; the score and stars follow the verdict.
- **The camera:** while the rover drives it plays a real drive film made from the rover's own camera frames: Perseverance's sol 130 autonomous drive (NASA PIA24743) and Curiosity crossing the Dingo Gap dune (NASA PIA17938). The game lays moving grain, scan lines and labels over it so it looks like a signal coming in from Mars, and says so. The longer the drive, the longer it plays (about 22 m a second, from 8 to 70 seconds). When the rover stops at a real photo spot, the camera shows the photo NASA's rover took there. Anywhere else it keeps the last picture of the drive until the rover drives again, and says that this picture was not taken at that spot.
- **Rover parts:** NASA's own 3D picture of each rover (an artist's concept, labelled as not a photo) with a dot on each part. The dots were placed by us and show roughly where each part is.
- **Real (NASA):** rover positions, tilts and elevations ([Perseverance](https://mars.nasa.gov/mmgis-maps/M20/Layers/json/M20_waypoints.json), [Curiosity](https://mars.nasa.gov/mmgis-maps/MSL/Layers/json/MSL_waypoints.json)); the orbital map tiles behind NASA's location maps ([Perseverance](https://science.nasa.gov/mission/mars-2020-perseverance/location-map/), [Curiosity](https://science.nasa.gov/mission/msl-curiosity/location-map/)); raw images taken inside the map ([Perseverance](https://mars.nasa.gov/mars2020/multimedia/raw-images/), [Curiosity](https://mars.nasa.gov/msl/multimedia/raw-images/)); map heights (MOLA gridded topography, NASA PDS); sunrise, sunset and temperatures at Gale (Curiosity REMS); radiation at Gale (Curiosity RAD via RadLab, May 2024); terrain roughness (MOLA); MMRTG 110 W at launch with 4.8 %/year decay; Perseverance battery 2,408 Wh and the 40 % rule; driving under 200 W; top speeds 152 and 144 m/h; rover masses 1,025 and 899 kg; the length of a Mars day; two real selfies (PIA26344, PIA24543), two artist's concepts (PIA22105, PIA14760) and two real drive films from the [NASA Image and Video Library](https://images.nasa.gov/) and Photojournal.
- **Our model:** a 30 W base load, the battery each test uses, the Curiosity battery's watt-hours (from 2 × 42 Ah at Perseverance's ratio), recharge times, the ten-day limit, the photo bonus, the bar scores, the rock-sample bar, the 10° limit and the stars. Weather and radiation come from Gale and stand in for Jezero too.
- **Offline:** everything runs from `data/nasa/` and `public/nasa/` (about 41 MB: 26 MB of map tiles, plus the photos, pictures and drive films), refreshed with `npm run data:rovers`. The one exception is **Load newest photos** on the My photos tab, which needs internet and says so.
- **Signal delay:** the Earth to Mars light time on 30 Mar 2029, 5.4 minutes, from JPL Horizons (`data/nasa/ops-dates.json`), plus the ship's relay hand-off (our model) unless Communications is 5 or more. It is shown on the rover camera, at Rover Comms and at Mission Ops. The other two operations dates in that file are not used by the rover expedition.

## Simulated rules in brief

| Ship | Payload | Budget | Rover battery | Relay hand-off |
| --- | ---: | ---: | ---: | ---: |
| Odyssey | 18 kg | 100 cr | 100% | 3 min |
| Atlas | 25 kg | 113 cr | 92% | 3 min |
| Vector | 12 kg | 88 cr | 100% | 2 min |

- **Instruments:** IR-S1 costs 42 cr and weighs 7 kg; rover drilling uses 300 Wh with it. GPR-2 costs 68 cr and weighs 13 kg; drilling uses 380 Wh.
- **Power:** Life support 3 and Communications 4 are needed to send the rover out. Communications 5 is a direct link with no relay hand-off. Research 3 or more makes drilling use 30 % less battery.
- **Tasks:** battery balancing makes driving draw 30 W less; cargo adds 5 cr; water adds +5 to the base score; calibration gets drilled samples analysed; the medical check clears the habitat.
- **Budget:** the supply budget pays for the instrument. Nothing else is charged.

## Acceptance scenarios (verified by `npm test` and in the browser)

1. Place two points and deploy: the rover stops at the last point, which becomes spot B, and the forecast matches what happened.
2. At a flat real stop, all four tests with a calibrated instrument give a good place.
3. A steep real stop is a bad place, and the base can still be built there for one star.
4. A drive longer than the battery ends in safe mode partway. Recharging ends safe mode, refills the battery and uses up Mars days (about 2.5 for Curiosity, about 1.1 for Perseverance). It runs on a countdown of one Mars hour each second, and can be left, stopped early or skipped.
5. Station choices change the rover: ship charge, battery balancing, research power, the water purifier, and Communications ≥ 4 to deploy.
6. Curiosity at Gale plays the same way.
7. One rover for the whole mission: a second choice is refused, and each rover's pros and cons match the numbers.
8. Ten Mars days: driving and recharging use them up, a drive must fit in the time left, and when they run out the base can still be built on a visited spot.
9. A real photo spot the rover parks at or drives past joins the album by itself and adds +2 to the score (at most +10). It costs no battery, counts once, and the forecast names the spots a drive will pass.
10. Two tabs: both astronauts appear and move, power syncs, avatars hide and reappear, and solo works with the server offline.

## Project layout

- `data/nasa/`: NASA snapshots. `earth-mars-geometry.json` (JPL Horizons) and `curiosity-weather.json` (Curiosity REMS) are the trimmed downloads; `ops-dates.json` is the small extract the game reads. Each file records its source, provider and retrieval date. The rover expedition adds `<rover>-area.json` (real stops, photos, MOLA heights), `<rover>-satellite.json` (orbital map tiles), `gale-rems-recent.json`, `mola-roughness-regions.json` and `site-references.json` (radiation, films, pictures); their image and video files are in `public/nasa/`.
- `src/data/`: typed access to that extract, plus the source lines the game shows.
- `src/core/`: pure TypeScript rules (data, power, tasks, mission, co-op protocol validation, `survey.ts` for the map, driving, tests, photos, recharging and site scores, `rovers.ts` for rover facts and parts). This code is shared with the server and tests.
- `src/art/geo.json`: station and Mars geometry, read by both the art generator and the game.
- Station code: `src/game/deck.ts` (typed geometry), `src/game/stationFx.ts` (mission state drawn on the deck), `src/game/nav.ts` (the floor guide's route), `src/ui/ops.ts` (Mission Ops), `src/ui/stationHud.ts` (objective, deck map).
- `src/game/`: Phaser scenes (station and Mars) and input.
- `src/ui/`: title (with its WebGL2 backdrop in `titleScene.ts`), fleet, crew, launch, task panels, rover operations (`roverView.ts`, `roverPanels.ts`, `mapView.ts`), and the report.
- `server/`: the Colyseus `spacer_power` room.
- `scripts/`: the art generator, the NASA downloads (`fetch-nasa-data.mjs` for the operations dates, `fetch-rover-data.mjs` for the rover expedition) and the operations-date builder (`build-ops-dates.mjs`). `test/` holds the tests.

## Current local review build

The station now has eight connected modules: Cupola, Docking Port, Node 3, Node 1, US Lab, Node 2, Greenhouse and Comms. It keeps the launch field already on main (Space Shuttle, Falcon 9 + Crew Dragon, Atlas V + Starliner), with cargo effects carried into the station and rover. The rover saves nearby photos automatically and recharges on a countdown that continues while the pilot works on the station.

The greenhouse area and its terminals are unfinished placeholders. Its simulation, visual layer and draft tests are preserved for later work; they are not connected to gameplay. At the user's request, `npm test` / `npm run check` validate the active launch, station, co-op, rover, data and ownership suites. `npm run test:greenhouse` runs the unfinished greenhouse suite separately (13 known failures when first checked); `npm run test:all` includes both active and draft suites. No greenhouse implementation was changed during this integration.
